# Complete Platform Deployment Guide: TMF 915 AI Management

This guide covers the end-to-end deployment of the TMF 915 AI Management API and all its dependencies. The ecosystem uses Docker and Docker Compose for simple, reproducible deployments.

## Architecture Overview
*   **MySQL (Port 3306):** Relational database storing data for both Keycloak (identity) and the TMF915 API (`aim915db`).
*   **Keycloak (Port 8080):** Identity and Access Management tool serving OAuth2/JWT tokens for the application.
*   **MinIO (Port 9010):** S3-compatible object storage used by MLflow to store deep learning model artifacts.
*   **MLflow (Port 5000):** Machine Learning lifecycle tool used to track metrics, parameters, and models.
*   **TMF 915 API (Port 13082):** Spring Boot backend API bridging the TMForum specifications with MLflow model management.

---

## Prerequisites
*   **Docker & Docker Compose v2+** installed on the host.
*   **Java 21 & Maven** (required if you wish to build the Spring Boot application from source initially).
*   **Python 3** (used strictly by the Docker healthcheck mechanisms in the TMF915 container).

---

## Step 1: Building the TMF915 Application

Before spinning up the main API container, you need to compile the Spring Boot application and generate the required `.jar` file so that the Docker image can be built.

1.  **Build the project using Maven:**
    ```bash
    mvn clean package -DskipTests
    ```
    This will generate the required `controllers-tmf915-4.0.0.jar` inside the `target/` directory.

---

## Step 2 & 3: Deploying the Stack

The primary `docker-compose.yml` uses Docker Compose **profiles** to let you flexibly pick which components to run locally.

### Option A: Standard Deployment (External MLflow & MinIO)
If your MLflow and MinIO are already running remotely (at `172.16.100.94` or similar), you can simply launch the core stack (MySQL, Keycloak, and TMF915):

```bash
docker compose up -d
```
*(By default, the `tmf915` service connects to the external IPs specified as fallbacks in the compose file).*

### Option B: Full Local Deployment (Everything via Docker)
If you want to spin up MinIO and MLflow locally along with the core services, you use the `full` profile and override the connection URIs so the API connects to the local containers:

```bash
MLFLOW_TRACKING_URI=http://mlflow:5000
```
```bash
MLFLOW_S3_ENDPOINT_URL=http://minio:9000 
```
```bash
docker compose --profile full up -d
```

*Wait a few moments for Keycloak to finish initializing before the TMF915 API boots up successfully.*

## Application Configuration Configuration (`application.yml`)

The parameters in `src/main/resources/application.yml` control exactly how the TMF915 API interfaces with the databases, MLflow, Keycloak, and Docker. Below are the key modifiable configurations you might adjust during integration:

### Modifiable Parameters

*   **`server.port`** (Default: `13082`) - The port the Spring Boot application exposes.
*   **`spring.datasource.url` / `username` / `password`** - Connections for the local or external MySQL database where API state is managed.
*   **`spring.security.oauth2.resourceserver.jwt.*`** - Security locations defining the OAuth2 keys fetched from Keycloak to validate standard tokens on incoming requests.

#### MLflow & Deployment Parameters (`mlflow.*`)
*   **`mlflow.tracking-uri`**: The HTTP location of the backing MLflow service.
*   **`mlflow.s3-endpoint-url` / `s3-access-key` / `s3-secret-key`**: The coordinates to the S3-compatible backend (MinIO) that physically stores the Model artifacts. Needs to match the environment variables tracked inside the docker composition.
*   **`mlflow.sync.interval-ms`**: (Default: `60000`/1 min). The frequency at which the engine queries MLflow to pull models and publish them into `AiModelSpecification`.
*   **`mlflow.docker.host`**: Vital for scaling AI Models. Leaving it blank targets your local docker engine. When running the Spring App inside a Docker container (as in the compose file), it is usually `unix:///var/run/docker.sock` bounding dynamically.
*   **`mlflow.docker.host-port-start` / `mlflow.docker.host-port-end`**: The randomized network range bounding models as they build endpoints on your server.
*   **`mlflow.docker.command-timeout-seconds`**: (Default: 30) If standard `build-docker` pipelines take longer depending heavily on container sizes from PyPI downloading, increase this to prevent silent truncates.

#### AIM915 Configurations (`aimodel.*`)
*   **`aimodel.specification.default-lifecycle-status`**: (Default `Active`). Automatically parses pulled MLflow instances natively as "Active" available API catalogs.
*   **`aimodel.deployment.serving-base-url`**: Exposed environment alias used inside generated definitions showing users where actual payloads are deployed.

## Examples: Using the TMF915 API (From Postman Collection)

Once the stack is successfully deployed, you can interact with it via the standard TMForum endpoints. The `postman/` directory contains a full collection you can import, but here are the core commands demonstrating the model deployment lifecycle.

*(Note: The examples rely on the API base URL. Replace `PUT_AI_MODEL_SPECIFICATION_ID_HERE` with the ID obtained from Step 1. Ensure you have obtained an access token if authentication is enabled.)*

### 0. (Optional) Get Keycloak Access Token
If your API deployment is secured via Keycloak, retrieve an access token first to authenticate subsequent calls:

```bash
ACCESS_TOKEN=$(curl -s -X POST "http://localhost:8080/auth/realms/openslice/protocol/openid-connect/token" \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -d "grant_type=password" \
     -d "client_id=osapiWebClientId" \
     -d "username=admin" \
     -d "password=openslice" | grep -o '"access_token":"[^"]*' | grep -o '[^"]*$')
     
echo "Token: $ACCESS_TOKEN"
```
*(Add `-H "Authorization: Bearer $ACCESS_TOKEN"` to the curl commands below)*

### 1. List Available AI Model Specifications
Fetch the available AI model specifications loaded in the database.

```bash
curl -X GET "http://localhost:13082/tmf-api/AiM/v4/aiModelSpecification?limit=50" \
     -H "Accept: application/json;charset=utf-8" \
     -H "Authorization: Bearer $ACCESS_TOKEN"
```

### 2. Deploy AI Model from Specification
Create a new AI Model instance and set its state to `reserved`, matching it to the target specification id. The deployment engine will automatically trigger the creation of a container (via MLflow) to serve the model.

*(Replace `{{dockerHost}}` with your Docker host target, e.g., `tcp://172.16.100.94:2375` or `unix:///var/run/docker.sock`)*

```bash
curl -X POST "http://localhost:13082/tmf-api/AiM/v4/aiModel" \
     -H "Content-Type: application/json;charset=utf-8" \
     -H "Accept: application/json;charset=utf-8" \
     -H "Authorization: Bearer $ACCESS_TOKEN" \
     -d '{
  "name": "my-ai-model-name",
  "description": "Deploy from existing AiModelSpecification",
  "state": "reserved",
  "aiModelSpecification": {
    "id": "PUT_AI_MODEL_SPECIFICATION_ID_HERE"
  },
  "software": [
    {
      "id": "mlflow-runtime",
      "name": "MLflow",
      "softwareVersion": "2.11.1"
    }
  ],
  "serviceCharacteristic": [
    {
      "name": "platform",
      "valueType": "string",
      "value": "mlflow"
    },
    {
      "name": "dockerHost",
      "valueType": "string",
      "value": "{{dockerHost}}"
    }
  ]
}'
```

### 3. Check Deployed Model Status
Use the ID returned in the previous request to poll the deployed model. Once successfully deployed, its state will switch to `active` and it will contain the endpoint and an `inferencePayloadExample`. If the deployment failed, it will revert to `designed` state and contain an error inside the `note` list.

```bash
curl -X GET "http://localhost:13082/tmf-api/AiM/v4/aiModel/PUT_DEPLOYED_AI_MODEL_ID_HERE" \
     -H "Accept: application/json;charset=utf-8" \
     -H "Authorization: Bearer $ACCESS_TOKEN"
```

### 4. Stop the Deployed AI Model
To scale down the container and turn off the model endpoint, simply patch the model state to `inactive`.

```bash
curl -X PATCH "http://localhost:13082/tmf-api/AiM/v4/aiModel/PUT_DEPLOYED_AI_MODEL_ID_HERE" \
     -H "Content-Type: application/json;charset=utf-8" \
     -H "Authorization: Bearer $ACCESS_TOKEN" \
     -d '{
  "state": "inactive"
}'
```

### 5. Delete the Deployed AI Model
To fully purge the model and any underlying containers created.

```bash
curl -X DELETE "http://localhost:13082/tmf-api/AiM/v4/aiModel/PUT_DEPLOYED_AI_MODEL_ID_HERE" \
     -H "Accept: application/json;charset=utf-8" \
     -H "Authorization: Bearer $ACCESS_TOKEN"
```

## Helpful Management Commands

*   **View active containers and health status:** 
    ```bash
    docker compose ps
    ```
*   **Tail real-time API logs:** 
    ```bash
    docker compose logs -f tmf915
    ```
*   **Stop environment safely:** 
    ```bash
    docker compose down
    ```
*   **Wipe environment completely & remove volumes (CAUTION - DELETES ALL DATA IN MYSQL):** 
    ```bash
    docker compose down -v
    ```
